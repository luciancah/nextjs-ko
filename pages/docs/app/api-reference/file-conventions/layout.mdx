`layout` 파일은 Next.js 애플리케이션에서 레이아웃을 정의할 때 사용됩니다.

```tsx filename="app/dashboard/layout.tsx" switcher
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
```

```jsx filename="app/dashboard/layout.js" switcher
export default function DashboardLayout({ children }) {
  return <section>{children}</section>
}
```

**root layout**는 루트 `app` 디렉터리의 최상위 레이아웃입니다. `<html>` 및 `<body>` 태그와 전역 공유 UI를 정의할 때 사용됩니다.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

## Reference

### Props

#### `children` (required)

레이아웃 컴포넌트는 `children` prop을 받아 사용해야 합니다. 렌더링 시 `children`은 레이아웃이 감싸는 라우트 세그먼트로 채워집니다. 주로 하위 [Layout](/docs/app/api-reference/file-conventions/page) (존재하는 경우) 또는 [Page](/docs/app/api-reference/file-conventions/page) 컴포넌트이며, 상황에 따라 [Loading](/docs/app/api-reference/file-conventions/loading) 또는 [Error](/docs/app/getting-started/error-handling) 같은 특수 파일이 될 수도 있습니다.

#### `params` (optional)

루트 세그먼트부터 해당 레이아웃까지의 [동적 라우트 매개변수](/docs/app/api-reference/file-conventions/dynamic-routes)를 담은 객체를 해결하는 Promise입니다.

예시:

```tsx filename="app/dashboard/[team]/layout.tsx" switcher
export default async function Layout({
  children,
  params,
}: {
  children: React.ReactNode
  params: Promise<{ team: string }>
}) {
  const { team } = await params
}
```

```jsx filename="app/dashboard/[team]/layout.js" switcher
export default async function Layout({ children, params }) {
  const { team } = await params
}
```

| Example Route                     | URL            | `params`                           |
| --------------------------------- | -------------- | ---------------------------------- |
| `app/dashboard/[team]/layout.js`  | `/dashboard/1` | `Promise<{ team: '1' }>`           |
| `app/shop/[tag]/[item]/layout.js` | `/shop/1/2`    | `Promise<{ tag: '1', item: '2' }>` |
| `app/blog/[...slug]/layout.js`    | `/blog/1/2`    | `Promise<{ slug: ['1', '2'] }>`    |

- `params` prop은 Promise이므로 `async/await` 또는 React [`use`](https://react.dev/reference/react/use) 함수로 값을 읽어야 합니다.
  - v14 이하에서는 `params`가 동기 prop이었습니다. 하위 호환을 위해 Next.js 15에서 동기 접근이 아직 가능하지만, 향후 제거될 예정입니다.

### Layout Props Helper

`LayoutProps`를 사용하면 디렉터리 구조에서 추론된 `params`와 named slots를 강타입으로 사용할 수 있습니다. `LayoutProps`는 전역에서 사용 가능합니다.

```tsx filename="app/dashboard/layout.tsx"
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* app/dashboard/@analytics 가 있으면 typed slot으로 접근 가능합니다: */}
      {/* {props.analytics} */}
    </section>
  )
}
```

> **Good to know**:
>
> - 타입은 `next dev`, `next build`, `next typegen` 중 생성됩니다.
> - 타입 생성 이후 `LayoutProps` helper는 전역에서 바로 사용 가능하며 import가 필요 없습니다.

### Root Layout

`app` 디렉터리는 반드시 루트 레이아웃을 포함해야 합니다. 일반적으로 `app/layout.js`입니다.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html>
      <body>{children}</body>
    </html>
  )
}
```

- 루트 레이아웃은 `<html>` 및 `<body>` 태그를 반드시 정의해야 합니다.
  - 루트 레이아웃에 `<head>` 태그(`<title>`, `<meta>` 등)를 수동으로 넣지 말고 [Metadata API](/docs/app/getting-started/metadata-and-og-images)를 사용하세요.
- 여러 루트 레이아웃을 만들 수 있습니다.
  - [route groups](/docs/app/api-reference/file-conventions/route-groups) 사용 (`app/(shop)/layout.js`, `app/(marketing)/layout.js`)
  - `app/layout.js`를 생략해 하위 디렉터리 레이아웃이 각 루트 레이아웃이 되도록 구성
  - 여러 루트 레이아웃 간 이동은 클라이언트 라우팅이 아니라 전체 페이지 로드를 유발합니다.
- 루트 레이아웃은 동적 세그먼트 하위에도 둘 수 있습니다. 예: [internationalization](/docs/app/guides/internationalization)의 `app/[lang]/layout.js`.

## Caveats

### Request Object

레이아웃은 탐색 중 클라이언트 캐시를 활용하기 때문에 raw request 객체에 직접 접근하지 않습니다.

`headers`와 `cookies` API를 [Server Components](/docs/app/getting-started/server-and-client-components) 및 Functions에서 사용하세요.

### Query params

[Pages](/docs/app/api-reference/file-conventions/page)와는 달리, Layout 컴포넌트는 `searchParams` prop을 받지 **않습니다**. 이는 공유 레이아웃이 [탐색 중에 다시 렌더링되지 않기](/docs/app/building-your-application/routing/linking-and-navigating#4-partial-rendering) 때문에, 탐색 간에 `searchParams`가 오래된 상태로 남을 수 있기 때문입니다.

클라이언트 측 탐색을 사용할 때, Next.js는 두 라우트 간의 공통 레이아웃 아래의 페이지 부분만 렌더링합니다.

예를 들어, 다음 디렉터리 구조에서, `dashboard/layout.tsx`는 `/dashboard/settings`와 `/dashboard/analytics` 모두에 대한 공통 레이아웃입니다:

`/dashboard/settings`에서 `/dashboard/analytics`로 이동할 때, `/dashboard/analytics`의 `page.tsx`는 서버에서 다시 렌더링되지만, `dashboard/layout.tsx`는 두 라우트 간에 공유되는 공통 UI이므로 다시 렌더링되지 않습니다.

이 성능 최적화는 레이아웃을 공유하는 페이지 간의 탐색을 더 빠르게 하여, 페이지에 대한 데이터 페칭과 렌더링만 실행되도록 합니다. 대신, 공유 레이아웃이 자체 데이터를 페칭할 필요는 없습니다.

`dashboard/layout.tsx`가 다시 렌더링되지 않기 때문에, 레이아웃 서버 컴포넌트의 `searchParams` prop이 탐색 후 **오래된** 상태로 남을 수 있습니다.

대신, 페이지 [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional) prop 또는 클라이언트 컴포넌트에서 최신 `searchParams`로 클라이언트에서 다시 렌더링되는 [`useSearchParams`](/docs/app/api-reference/functions/use-search-params) 훅을 사용하십시오.

### Pathname

레이아웃은 `pathname`에 접근할 수 없습니다. 이는 레이아웃이 기본적으로 서버 컴포넌트이며, [클라이언트 측 탐색 동안 다시 렌더링되지 않기](/docs/app/building-your-application/routing/linking-and-navigating#4-partial-rendering) 때문에, 탐색 간에 `pathname`이 오래된 상태로 남을 수 있기 때문입니다. 오래된 상태를 방지하기 위해, Next.js는 라우트의 모든 세그먼트를 다시 페칭해야 하며, 이는 캐싱의 이점을 잃고 탐색 시 [RSC 페이로드](/docs/app/building-your-application/rendering/server-components#what-is-the-react-server-component-payload-rsc) 크기를 증가시킵니다.

대신, `pathname`에 의존하는 로직을 클라이언트 컴포넌트로 추출하여 레이아웃에 가져올 수 있습니다. 클라이언트 컴포넌트는 탐색 중에 다시 렌더링되지만 다시 페칭되지 않기 때문에, [`usePathname`](https://nextjs.org/docs/app/api-reference/functions/use-pathname)과 같은 Next.js 훅을 사용하여 현재 pathname에 접근하고 오래된 상태를 방지할 수 있습니다.

```tsx filename="app/dashboard/layout.tsx" switcher
import { ClientComponent } from '@/app/ui/ClientComponent'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <ClientComponent />
      {/* Other Layout UI */}
      <main>{children}</main>
    </>
  )
}
```

```jsx filename="app/dashboard/layout.js" switcher
import { ClientComponent } from '@/app/ui/ClientComponent'

export default function Layout({ children }) {
  return (
    <>
      <ClientComponent />
      {/* Other Layout UI */}
      <main>{children}</main>
    </>
  )
}
```

일반적인 `pathname` 패턴은 [`params`](#params-optional) prop으로도 구현할 수 있습니다.

자세한 내용은 [examples](/docs/app/building-your-application/routing/layouts-and-templates#examples) 섹션을 참조하십시오.
