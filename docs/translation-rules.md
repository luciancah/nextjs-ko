# Next.js KO Translation Rules

이 문서는 `nextjs-ko` 번역 작업에서 지속적으로 참고하는 운영 기준입니다.
원문 버전 업데이트 시(예: `v15.0.0-canary.82` -> `v16.1.6`) 모든 번역 PR은 이 문서를 따라야 합니다.

## 1) 문서 구조 규칙

- 헤딩(`##`, `###` 등)은 원문의 영문 헤딩을 유지합니다.
- 파일 경로/slug는 원문 구조를 최대한 유지합니다.
- `_meta.json` 내 문서 순서/그룹은 원문 네비게이션을 기준으로 맞춥니다.

## 2) 번역 스타일 규칙

- 기술 용어는 `docs/translation-glossary.csv`의 표준 번역을 우선 적용합니다.
- 코드 식별자, API 이름, 옵션 키, 파일명은 번역하지 않고 원문 그대로 유지합니다.
- 문장 톤은 평서형으로 통일하고, 불필요한 의역을 피합니다.
- 한국어로 번역이 어색한 용어는 영문 유지 또는 로마자 표기를 사용합니다.

## 3) 마크다운/코드 규칙

- 코드 블록은 원문 코드와 의미를 동일하게 유지합니다.
- 링크 URL은 원문을 유지하고, 링크 텍스트만 필요 시 번역합니다.
- 주의/경고/팁 블록은 레벨과 의미를 바꾸지 않습니다.
- 버전 표기(예: `v16.1.6`)와 날짜는 절대값으로 정확히 기재합니다.

## 4) 버전 업데이트 작업 규칙

- 변경 원문은 반드시 `v15.0.0-canary.82...v16.1.6` diff 근거로 작업합니다.
- 파일 상태를 `A(신규)`, `M(수정)`, `D(삭제)`, `R(이동)`로 분류해 처리합니다.
- `D`/`R` 항목은 KO 쪽 orphan 경로가 남지 않도록 함께 정리합니다.

## 5) PR 체크리스트

아래 항목을 PR 본문에 체크합니다.

- [ ] 원문 기준 버전과 diff 링크를 명시했다.
- [ ] `docs/translation-rules.md`를 확인하고 규칙을 적용했다.
- [ ] `docs/translation-glossary.csv` 기준으로 용어를 맞췄다.
- [ ] 신규 용어가 있으면 용어집을 먼저 업데이트했다.
- [ ] 문서 빌드/링크 확인을 완료했다.

## 6) 예외 처리

- 원문이 모호하거나 충돌하면 임의 해석 대신 PR에 쟁점을 기록합니다.
- deprecated/legacy 문서는 원문 상태를 우선 반영하고, 필요 시 주석으로 맥락을 추가합니다.
- 규칙 변경이 필요하면 문서(`translation-rules.md`)를 먼저 수정한 뒤 번역 PR을 진행합니다.
